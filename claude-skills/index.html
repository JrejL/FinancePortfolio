How a Skill Works

  1. Install it. One command copies the skill into Claude Code's skills folder, so it works in every project. A ZIP download works too.
  2. Ask in plain words. Each skill names the requests it answers, so Claude knows when to use it.
  3. Claude follows the steps. The skill's SKILL.md holds the steps, what done means and the guardrails. Its scripts handle what Claude cannot do alone, like asking macOS for permission.

A Claude Code skill that writes a short summary of each day you worked into its own Apple Calendar, so you can look back and see what happened on any date.

Ask "log today to my calendar" and Claude drafts a title and a few sentences for the day, shows you, and on your yes adds it as an all day event in a separate calendar called Workday Log. It can also backfill past days from your git history.

What you need

  • A Mac on macOS 14 or newer
  • Xcode Command Line Tools (xcode-select --install)
  • Claude Code

Safety

  • Events go only into the "Workday Log" calendar. Your own calendars are never touched.
  • Claude shows you every event before writing it.
  • Running it twice does not duplicate events.
  • To remove everything, delete the "Workday Log" calendar in the Calendar app.
  • The calendar syncs to iCloud, so the skill tells Claude to leave out secrets and private details.

Setup

install.sh asks a few quick questions (press Enter to keep the default). If you skip them, Claude asks on first use. Rerun sh ~/.claude/skills/day-to-calendar/scripts/setup.sh any time to change them.

QuestionDefaultNotes
Calendar nameWorkday LogThe separate calendar events go into
ColortealA name (red, orange, yellow, green, teal, blue, purple, pink, brown, gray) or a hex like #1A73E8
Event lengthall dayOr a number of minutes; then you also pick a start time

Answers are saved in ~/.config/day-to-calendar/config.json, which you can also edit by hand. Changing the color updates the existing calendar the next time it runs.

Why it ships its own tiny app

macOS only shows the calendar permission prompt to an app that declares why it wants access. Claude's app does not, so the request fails silently. DayCal.app is built on your Mac from scripts/daycal.swift, carries the declaration, and is the only thing that touches your calendar. Read the source; it is about 80 lines.

# day-to-calendar: one calendar event per worked day

**Done =** each requested day has one all day event in the configured calendar, and the tool's output line confirms how many were added.

## Procedure
0. Settings live in `~/.config/day-to-calendar/config.json`. If that file is missing, run setup first: ask the user these six things (offer the default in brackets), then write the file with the keys shown, or tell them they can run `sh scripts/setup.sh` themselves.
   - Calendar name ["Workday Log"] → `calendar`
   - Color [teal]: red, orange, yellow, green, teal, blue, purple, pink, brown, gray, or a hex → `color`
   - Event length [all day] or a number of minutes → `all_day` (true/false), `duration_minutes`, and `start_time` like "17:00" if timed
   - Longest title [8 words] → `title_max_words`
   - Longest note [4 sentences] → `notes_max_sentences`
   Read the file on every run and obey the length limits when drafting.
1. Pick the days. Default is today. For a backfill, ask which dates, or use the days that have git commits or session history.
2. Gather what happened per day. Use, in this order: the current conversation, `git log --since="<date> 00:00" --until="<date> 23:59" --oneline` in the working repo, and any notes the user points to. Do not invent work you cannot see.
3. Write one event per day: a title within `title_max_words` (default 8) naming the main outcome, and notes within `notes_max_sentences` (default 4) in plain language on what was done, decided, and left open.
4. Leave out secrets, keys, passwords, balances, and private details of other people. The calendar syncs to iCloud.
5. Show the user the events and wait for a yes. The calendar is theirs.
6. Save them as `/tmp/day-events.json` in this shape:
   `[{"date":"2026-09-24","title":"Shipped the login fix","notes":"..."}]`
7. Check access: `sh scripts/daycal.sh status`. If it says `notDetermined`, run `sh scripts/daycal.sh request` and tell the user to click Allow in the macOS dialog. If it says `denied`, point them to System Settings, Privacy and Security, Calendars.
8. Write: `sh scripts/daycal.sh add /tmp/day-events.json`. Report the output line as printed.

## Guardrails
- Events go only into the dedicated calendar (the `calendar` setting, default "Workday Log"). Never touch the user's other calendars.
- Running twice is safe: an event with the same title on the same day is skipped.
- To undo everything, the user deletes that one calendar in the Calendar app.
- The first run compiles the helper and needs Xcode Command Line Tools (`xcode-select --install`). macOS 14 or newer.

## Related
The helper source is `scripts/daycal.swift`. Rebuild with `sh scripts/make-app.sh` after editing it.
Show daycal.sh
#!/bin/sh
# daycal.sh <status|request|add events.json>: runs DayCal.app as its own process (so macOS asks and
# remembers calendar access for it, not for whoever called it) and prints what it said.
# Set DAYCAL_CALENDAR to change the calendar name (default "Workday Log").
here=$(cd "$(dirname "$0")" && pwd)
[ -d "$here/DayCal.app" ] || sh "$here/make-app.sh" >/dev/null
out=$(mktemp); err=$(mktemp)
file=""; [ -n "$2" ] && file=$(cd "$(dirname "$2")" && pwd)/$(basename "$2")
open -W -n --stdout "$out" --stderr "$err" ${DAYCAL_CALENDAR:+--env "DAYCAL_CALENDAR=$DAYCAL_CALENDAR"} "$here/DayCal.app" --args "${1:-status}" $file 2>/dev/null
# open -W cannot always track a background app, so also wait for the process to finish (up to 15 minutes)
i=0; while pgrep -qf "DayCal.app/Contents/MacOS/DayCal" && [ $i -lt 4500 ]; do sleep 0.2; i=$((i+1)); done
cat "$out" "$err"; rm -f "$out" "$err"
Show daycal.swift
// daycal.swift: writes one all day event per worked day into a dedicated Apple Calendar, through EventKit.
//   daycal status              -> the calendar access macOS has granted
//   daycal request             -> asks macOS for full calendar access (click Allow once)
//   daycal add <events.json>   -> writes the events, skipping any with the same title on the same day
// events.json: [{"date": "2026-09-24", "title": "...", "notes": "..."}]
// Everything goes into one calendar (default name "Workday Log"), so you can
// hide or delete it in one go and it never mixes with your own events.
import EventKit
import Foundation

let store = EKEventStore()
let args = CommandLine.arguments

// Settings live in ~/.config/day-to-calendar/config.json (written by setup.sh); DAYCAL_* env vars override.
let cfgPath = NSHomeDirectory() + "/.config/day-to-calendar/config.json"
let cfg = (FileManager.default.contents(atPath: cfgPath).flatMap { try? JSONSerialization.jsonObject(with: $0) as? [String: Any] }) ?? [:]
let env = ProcessInfo.processInfo.environment
let calendarName = env["DAYCAL_CALENDAR"] ?? (cfg["calendar"] as? String) ?? "Workday Log"
let colorSetting = env["DAYCAL_COLOR"] ?? (cfg["color"] as? String) ?? "teal"
let allDay = (cfg["all_day"] as? Bool) ?? true
let startTime = (cfg["start_time"] as? String) ?? "17:00"      // used when all_day is false
let minutes = (cfg["duration_minutes"] as? Int) ?? 60          // used when all_day is false

func parseColor(_ s: String) -> CGColor {
    let named: [String: String] = ["red": "E5484D", "orange": "F76B15", "yellow": "F5C400", "green": "30A46C",
        "teal": "21A08C", "blue": "0090FF", "purple": "8E4EC6", "pink": "E93D82", "brown": "A18072", "gray": "8B8D98"]
    var hex = (named[s.lowercased()] ?? s).replacingOccurrences(of: "#", with: "")
    if hex.count != 6 { hex = "21A08C" }
    let v = UInt32(hex, radix: 16) ?? 0x21A08C
    return CGColor(red: CGFloat((v >> 16) & 255) / 255, green: CGFloat((v >> 8) & 255) / 255, blue: CGFloat(v & 255) / 255, alpha: 1)
}

func statusWord() -> String {
    switch EKEventStore.authorizationStatus(for: .event) {
    case .notDetermined: return "notDetermined"
    case .restricted: return "restricted"
    case .denied: return "denied"
    case .fullAccess: return "fullAccess"
    case .writeOnly: return "writeOnly"
    case .authorized: return "authorized"
    @unknown default: return "unknown"
    }
}

func workCalendar() -> EKCalendar? {
    if let found = store.calendars(for: .event).first(where: { $0.title == calendarName }) {
        let want = parseColor(colorSetting)
        if found.cgColor != want && found.allowsContentModifications { found.cgColor = want; try? store.saveCalendar(found, commit: true) }
        return found
    }
    let cal = EKCalendar(for: .event, eventStore: store)
    cal.title = calendarName
    cal.cgColor = parseColor(colorSetting)
    let sources = store.sources
    cal.source = sources.first(where: { $0.sourceType == .calDAV && $0.title.lowercased().contains("icloud") })
        ?? store.defaultCalendarForNewEvents?.source
        ?? sources.first(where: { $0.sourceType == .local })
    do { try store.saveCalendar(cal, commit: true); return cal } catch { print("could not make the \(calendarName) calendar: \(error)"); return nil }
}

let cmd = args.count > 1 ? args[1] : "status"
if cmd == "status" {
    print(statusWord())
} else if cmd == "request" {
    let sem = DispatchSemaphore(value: 0)
    store.requestFullAccessToEvents { granted, error in
        print(granted ? "granted" : "not granted \(String(describing: error))")
        sem.signal()
    }
    _ = sem.wait(timeout: .now() + 900)
} else if cmd == "add" {
    guard args.count > 2, let data = FileManager.default.contents(atPath: args[2]),
          let list = try? JSONSerialization.jsonObject(with: data) as? [[String: String]] else {
        print("usage: add <events.json>"); exit(1)
    }
    guard let cal = workCalendar() else { exit(1) }
    let fmt = DateFormatter(); fmt.dateFormat = "yyyy-MM-dd"; fmt.timeZone = TimeZone.current
    var added = 0, skipped = 0
    for e in list {
        guard let day = fmt.date(from: e["date"] ?? ""), let title = e["title"] else { continue }
        let end = Calendar.current.date(byAdding: .day, value: 1, to: day)!
        let existing = store.events(matching: store.predicateForEvents(withStart: day, end: end, calendars: [cal]))
        if existing.contains(where: { $0.title == title }) { skipped += 1; continue }
        let ev = EKEvent(eventStore: store)
        ev.calendar = cal
        ev.title = title
        ev.notes = e["notes"]
        if allDay {
            ev.isAllDay = true
            ev.startDate = day
            ev.endDate = day
        } else {
            let hm = startTime.split(separator: ":").compactMap { Int($0) }
            let start = Calendar.current.date(bySettingHour: hm.first ?? 17, minute: hm.count > 1 ? hm[1] : 0, second: 0, of: day) ?? day
            ev.startDate = start
            ev.endDate = start.addingTimeInterval(TimeInterval(minutes * 60))
        }
        do { try store.save(ev, span: .thisEvent, commit: false); added += 1 } catch { print("failed \(e["date"] ?? ""): \(error)") }
    }
    do { try store.commit() } catch { print("commit failed: \(error)") }
    print("added \(added), already there \(skipped), calendar \(cal.title) on \(cal.source?.title ?? "?")")
} else {
    print("unknown command \(cmd); use status, request or add <events.json>"); exit(1)
}
Show make-app.sh
#!/bin/sh
# make-app.sh: builds DayCal.app from daycal.swift. Claude's own app cannot ask macOS for calendar access
# (no calendar usage line in its Info.plist, so macOS refuses without ever showing a prompt), so the tool
# runs as its own tiny app that carries the line. Click Allow once; the grant is tied to this build's
# signature, so rebuild only when daycal.swift changes (and expect to click Allow again).
set -e
here=$(cd "$(dirname "$0")" && pwd)
app="$here/DayCal.app"
rm -rf "$app"
mkdir -p "$app/Contents/MacOS"
swiftc -O -target "$(uname -m)-apple-macos14" "$here/daycal.swift" -o "$app/Contents/MacOS/DayCal"
cat > "$app/Contents/Info.plist" <<PLIST
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE plist PUBLIC "-//Apple//DTD PLIST 1.0//EN" "http://www.apple.com/DTDs/PropertyList-1.0.dtd">
<plist version="1.0"><dict>
<key>CFBundleIdentifier</key><string>com.gmurad.daycal</string>
<key>CFBundleName</key><string>DayCal</string>
<key>CFBundleExecutable</key><string>DayCal</string>
<key>CFBundlePackageType</key><string>APPL</string>
<key>CFBundleShortVersionString</key><string>1.0</string>
<key>LSUIElement</key><true/>
<key>LSMinimumSystemVersion</key><string>14.0</string>
<key>NSCalendarsFullAccessUsageDescription</key><string>DayCal writes a short summary of each day you worked into its own calendar.</string>
<key>NSCalendarsUsageDescription</key><string>DayCal writes a short summary of each day you worked into its own calendar.</string>
</dict></plist>
PLIST
codesign --force -s - "$app"
echo "built $app"
Show setup.sh
#!/bin/sh
# setup.sh: asks a few questions and saves your answers to ~/.config/day-to-calendar/config.json.
# Press Enter to accept the value in [brackets]. Run it again any time to change your answers.
dir="$HOME/.config/day-to-calendar"; mkdir -p "$dir"
ask() { printf "%s [%s]: " "$1" "$2" >&2; read -r a; a="${a:-$2}"; printf "%s" "$a" | tr -d "\"\\\\"; echo; }
echo "day-to-calendar setup" >&2
cal=$(ask "Calendar name" "Workday Log")
color=$(ask "Calendar color (red, orange, yellow, green, teal, blue, purple, pink, brown, gray, or a hex like #1A73E8)" "teal")
len=$(ask "Event length: 'allday' or a duration in minutes (for example 30 or 60)" "allday")
start="17:00"; mins=60; allday=true
case "$len" in allday|"") ;; *[!0-9]*) echo "Not a number, using all day." >&2 ;; *) allday=false; mins=$len; start=$(ask "What time should it start (24 hour, like 17:00)" "17:00") ;; esac
words=$(ask "Longest title, in words" "8")
sent=$(ask "Longest note, in sentences" "4")
cat > "$dir/config.json" <<JSON
{
  "calendar": "$cal",
  "color": "$color",
  "all_day": $allday,
  "start_time": "$start",
  "duration_minutes": $mins,
  "title_max_words": $words,
  "notes_max_sentences": $sent
}
JSON
echo "Saved to $dir/config.json" >&2
